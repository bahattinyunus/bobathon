Shortest Path Algorithms: Study Sheet

Comprehensive review of graph representations, BFS, Dijkstra, A*, and Bellman-Ford with CampusRoute engineering applications.

1. Key Ideas

Graph Representation

  • Vertices (V): Buildings and path junctions. Edges (E): Walkways with non-negative weights in meters.
  • Adjacency List: Memory O(V + E). Optimal for campus navigation because campus graphs are sparse (each node connects to ~3 neighbors).
  • Adjacency Matrix: Memory O(V²). Inefficient for sparse networks.

The 4 Algorithms

  • BFS (Breadth-First Search): Level-by-level traversal using a FIFO Queue. Finds shortest paths strictly in number of edges (hops). Only minimizes metric distance if all edges have equal positive weight. Time: O(V + E).
  • Dijkstra's Algorithm: Greedy single-source shortest path for graphs with non-negative edge weights. Maintains a min-heap (Priority Queue). Settle closest unfinished vertex, relax edges, and skip already settled nodes (lazy deletion). Time: O((V + E) log V).
  • A* (A-Star): Guided Dijkstra using a heuristic function f(v) = g(v) + h(v), where g(v) is exact distance so far and h(v) estimates remaining distance to goal. Guaranteed optimal if h is admissible (never overestimates). Euclidean straight-line distance is admissible on a 2D campus map.
  • Bellman-Ford: Dynamic programming algorithm relaxing all edges V - 1 times. Handles negative edge weights and detects negative cycles. Time: O(V × E).

CampusRoute Engineering Applications

  • Step-free Routing ("Avoid stairs"): Filter out edges flagged with stairs prior to running Dijkstra. Does not require a new algorithm.
  • Via Detours: Compute two chained Dijkstra runs (Start → Via, then Via → Goal) and concatenate the paths.
  • Walking Estimates: Total route meters divided by average walking speed (80 m/min), rounded up using ceil.

4. Common Exam Traps & Error Corrections

Factual Error in Draft Lecture Notes:

Quote from notes: “IMPORTANT: Dijkstra works with negative edge weights as long as there is no negative cycle — prof said this is a common exam question”

The Correction (Essential Exam Fact):

This claim is FALSE. Dijkstra's algorithm cannot guarantee correct shortest paths in graphs with negative edge weights, even if there are no negative cycles.

Why: Dijkstra's greedy invariant assumes that once a vertex is popped from the min-heap and marked settled, its recorded distance is final. A negative edge encountered later could provide a shorter path to an already settled vertex, which Dijkstra will never revisit (or will handle inefficiently if re-opened). For negative edge weights, use Bellman-Ford.

Counter-Example: Consider vertices S, A, B. Edges: S → A (weight 4), S → B (weight 2), B → A (weight -5). Settle S. Next closest is B (dist 2). Then B settles, relaxes A to 2 + (-5) = -3. But if Dijkstra popped A first in a graph where A had smaller initial edge, A would never be updated.

Other Key Traps

  • BFS is not for weighted graphs: 2 hops of 100m (200m) is worse than 3 hops of 30m (90m). BFS only counts hops.
  • Admissibility of Heuristics: If h(v) overestimates even by 1 meter, A* can return a suboptimal path. Euclidean straight-line distance is always admissible because a straight line is the shortest distance between two points in Euclidean space.
  • Heap Tie-Breaking in Python: When storing (dist, node) in heapq, equal distances cause Python to compare node objects. If custom node objects don't define <, it raises a TypeError. Solution: push (dist, count, node) using itertools.count().

5. Self-Test Questions

Q1: Why is an adjacency list preferred over an adjacency matrix for CampusRoute?

CampusRoute maps are sparse graphs where each building or junction connects to only 3-4 walkways. An adjacency list uses O(V + E) memory, whereas an adjacency matrix consumes O(V²), wasting space on thousands of zero entries and slowing neighbor iteration.

Q2: Does Dijkstra's algorithm work with negative edge weights if there are no negative cycles?

No. Dijkstra assumes edge weights are non-negative so that distance labels only grow. A negative edge can invalidate previously settled vertices. Bellman-Ford must be used when negative weights exist.

Q3: What makes a heuristic admissible in A*, and why is Euclidean distance admissible on campus?

A heuristic h(v) is admissible if it never overestimates the true cost to reach the goal: h(v) ≤ h*(v) for all v. Euclidean (straight-line) distance is admissible on a campus map because the physical straight line is the absolute minimum distance between two coordinate points; no walkway can be shorter than straight line.

Q4: How does CampusRoute implement "step-free routing" without writing a new algorithm?

It filters the graph edges before routing, omitting any edge flagged with stairs: true, and then executes standard Dijkstra on the filtered graph.

Q5: What is lazy deletion in Dijkstra's priority queue, and why is it used in Python's heapq?

Standard binary heaps do not support efficient decrease-key operations. Instead of updating an existing element's key in the heap, Dijkstra pushes a new tuple (new_dist, v). When a node is popped, if it has already been settled (marked in a done set), it is simply skipped (lazily discarded).
